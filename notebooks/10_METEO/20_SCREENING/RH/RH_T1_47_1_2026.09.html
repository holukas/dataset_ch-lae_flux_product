MeteoScreening from database (InfluxDB)

Modified

27 October 2026

*****Notebook version: 20 (18 Oct 2026) Author: Lukas Hörtnagl (holukas@ethz.ch) Documentation**: diive.readthedocs.io



ℹ️ About this notebook

Downloads raw meteo data from InfluxDB, screens and corrects them at high resolution, resamples them to RESAMPLING_FREQ and uploads the result to the database. Screening uses StepwiseMeteoScreeningDb. Download and upload use InfluxIO, which needs pip install "diive[all]".

Screening is stepwise. Run a test, check its preview, then commit it with mscr.addflag(). At the end, all committed flags are combined into one quality flag, QCF.

Run All applies no outlier test and no correction, because they are all commented out. It still resamples, and it uploads only with UPLOAD = True.



⏱️ Timestamp convention (important)

The database stores all timestamps in UTC as TIMESTAMP_END, the end of the averaging interval. TIMEZONE_OFFSET_TO_UTC_HOURS sets the local time frame of the notebook, e.g. 1 for UTC+01:00. START, STOP, typed dates, the day/night split and day boundaries all use this frame. The download converts from UTC to this frame, the upload converts back. With a sub-daily RESAMPLING_FREQ such as '30min' the stored values are therefore the same for any offset. With '1D' the day boundaries follow the offset, so the daily values depend on it.

The raw data in the database are already in UTC, whatever clock the logger used. Use one fixed offset for every month, e.g. 1 (CET) also in summer. Changing it shifts START, STOP and typed dates, which leaves a gap or an overlap between runs.

Timestamps at each stage:

Stage Timezone Convention Done by
Database UTC TIMESTAMP_END InfluxDB
After dbc.download(..., timezone_offset_to_utc_hours=N) local (UTC+N) TIMESTAMP_END InfluxIO
During screening local TIMESTAMP_MIDDLE (converted internally) StepwiseMeteoScreeningDb
After mscr.resample() local back to TIMESTAMP_END diive
After dbc.upload_singlevar(..., timezone_offset_to_utc_hours=N) UTC TIMESTAMP_END InfluxIO

Dates for manual removal and Set a time range to a value are local TIMESTAMP_END, as in the downloaded data.



✏️ User settings (please adjust)

Adjust these before running.

Site - SITE, SITE_LAT, SITE_LON: site ID and coordinates. The coordinates set the day/night split.

Variables to screen - FIELDS: one or more variable names exactly as stored in the database (the InfluxDB _field). - MEASUREMENT: exactly one measurement that holds these variables.

Time range to screen - START, STOP: each one second after a RESAMPLING_FREQ boundary, e.g. '2026-03-01 00:00:01' and '2026-04-01 00:00:01' for March. Timestamps mark the END of each interval, so the record at 2026-03-01 00:00:00 belongs to February. These values cover the records ending after 2026-03-01 00:00 up to and including 2026-04-01 00:00. The upload deletes the same range before writing. Other values stop the notebook in Auto settings.

Data settings - TIMEZONE_OFFSET_TO_UTC_HOURS: local time frame of this run, one fixed offset without daylight saving time, see Timestamp convention. - DATA_VERSION: data version of the source data (raw). - DIRCONF: local folder with the database connection config.

Resampling - RESAMPLING_FREQ: target time resolution of the screened data. - RESAMPLING_AGG: 'mean' or 'sum'. Use 'sum' only for variables that accumulate over the interval.

Upload - UPLOAD: False runs everything except the upload. Set True only for the run that should write the result. The upload replaces the stored values between START and STOP.

🔍 Outlier detection

Each method has a test cell and an mscr.addflag() cell. Rerun a test with other settings as often as needed: mscr.addflag() commits the latest run. Run only the methods your variable needs.

Day and night. With separate_day_night=True the statistic is computed separately for daytime and nighttime, split by the site coordinates. Some methods also take separate daytime and nighttime thresholds, see the docs.

Windows. Window sizes are time spans such as '7D' or record counts. A time span becomes a record count at the time resolution of the data, so one setting works for 1-minute and 10-minute data. The window counts the records present, so across gaps it covers more calendar days. Local SD with separate_day_night=True counts only daytime or only nighttime records, so its window covers even more days: at 47° N in January about 16-20 days for daytime and 10-13 days for nighttime with '7D'. Data that change resolution are tested per resolution period.

All tests are commented out, so Run All applies none. The example settings are only a starting point and can remove valid data. To use a test, check its settings and notes, uncomment the test and its mscr.addflag() cell, then check the preview.

Hampel filter

Flags spikes far from the median of a sliding window, measured in median absolute deviations (MAD).

With use_differencing=True a single spike also removes both its neighbours at n_sigma 5.5. With repeat=True blocks of up to four bad values in a row are removed, also next to gaps and at the ends of the data. Of longer blocks only the outer values are removed. With separate_day_night=True daytime records are compared with the daytime records of the window, nighttime records with the nighttime ones. Records with up to 20 W m-2 potential radiation count as night, so twilight records are judged against the night statistics and can be removed. A sensor stuck at one value is not flagged, because the MAD is zero there. Use manual removal or Set exact values to missing for that. Docs: flag_outliers_hampel_test, Hampel.

Remove radiation zero offset

For shortwave radiation and PAR, which read below zero at night. The correction runs in this order: 1. Night: records with potential radiation below 0.001 W m-2. 2. Daily offset: the mean of the night values of each calendar day, i.e. the night before sunrise and the night after sunset of that date. All records of the day get this one value, there is no interpolation between days. Days without night values get the median offset of all days. 3. Subtract: the offset is subtracted from every record of the day, day and night. 4. Night to 0: night records are set to 0. 5. Clamp: values still below 0, e.g. daytime records at dawn and dusk, are set to 0. clamp_negatives=False keeps them.

The figure shows these steps with their counts, the daily offset, the diel cycle near zero after steps 3 and 5, the night values before and after subtracting the offset, and a summary. Docs: correction_remove_nighttime_zero_offset.

mscr.correction_remove_nighttime_zero_offset()

Remove relative humidity offset

For relative humidity that reads above 100 %. The correction runs in this order: 1. Find > 100 %: the values above 100 %. 2. Daily offset: for each day with such values, their mean minus 100. All records of the day get this one value. 3. Other days: the offset is interpolated linearly, record by record, between the nearest days with values above 100 %, and carried before the first and after the last such day. Without any value above 100 % the offset is 0. 4. Subtract: the offset is subtracted from every record. 5. Cap at 100 %: values still above 100 % are set to 100 %.

A single day above 100 % lowers every record of the period, so the result depends on the period screened. The figure shows these steps with their counts, the offset, the values near 100 %, the daily maximum and a summary. A pile just below 100 % without values above it means the sensor or logger caps the readings, and the correction finds no offset. Docs: correction_remove_relativehumidity_offset.

🔁 Resampling

Resample

Resamples the screened high-res series to RESAMPLING_FREQ, with TIMESTAMP_END timestamps ready for upload.

mincounts_perc sets how much of each target period the kept records must fill. Periods with less are missing. - 'mean': the share becomes a minimum number of records, rounded down. Below three, one record is enough, so 10-minute data resampled to 30 minutes need one record per half-hour. - 'sum': the kept records must cover that share of the period. For precipitation use 1 if partial sums are not wanted: a sum over a partly covered period is too low.

'mean' is an arithmetic mean and does not suit angles such as wind direction, which need a circular mean. This notebook does not compute one.

After changing the screened data, run this cell again, or the upload stops with an error. Docs: resample.

⬆️ Upload data to database

Existing screened data are overwritten. The upload writes to the processed bucket as data version meteoscreening_diive. With delete_from_db_before_upload=True it first deletes the stored values of each uploaded variable (same site, measurement, name and data version) between START and STOP, both included, then writes the new ones. Old values are removed also where the new data have no records, e.g. at the end of the period. Raw data, other variables and other data versions stay untouched.

The upload runs only with UPLOAD = True. It stops before deleting anything if: - SITE, MEASUREMENT, FIELDS, START, STOP or TIMEZONE_OFFSET_TO_UTC_HOURS differ from the values used for the download or the screening (mscr), e.g. after a new download without a new screening. The stored values would be shifted, or a neighbouring period deleted. Run the notebook again from Download. - a variable was resampled to a resolution other than RESAMPLING_FREQ, e.g. after an extra resample() call. Run Resample again.
