Merge IRGA72 Level-1 fluxes (2016-2026.09)

Modified

27 October 2026

notebook version: 2 (25 Oct 2026)

ℹ️ About this notebook

Merges the EddyPro FLUXNET output files of the Level-1 (final) flux calculations for the IRGA72 gas analyser into one continuous 30MIN dataframe and stores it in the external data folder as parquet. The flux processing chain joins it with the meteo data in its input notebook (30_FLUX_POST-PROCESSING_CHAIN/IRGA72/00_FPPC_IRGA72_INPUT_2016-2026.09), and 80_FINALIZE takes it into the collection of all data.

No value is computed or corrected here. Three things change in the incoming data:

  • Where two consecutive runs overlap, each record is taken whole from one of them, split at midnight (see the timestamp section below).
  • The six biomet columns that every run exported are dropped.
  • Columns that hold no value anywhere in the merged record are dropped.

The record is cut at PERIOD_END, the half-hour ending at midnight on 30 September 2026.

📇 Data sources

EddyPro FLUXNET output files (*_adv.csv), one per processing run, in the external data folder under 0_data/IRGA72-Level-1_fluxnet_2016-2026.09/. The whole IRGA72 record was re-run in September and October 2026, one run per setup period.

A run covers one or more setup periods, not a calendar year: 2017_1+2 is a single run over setup periods 1 and 2 of 2017, and a run boundary marks a hardware or configuration change. The merge therefore works on the timestamps inside the files, not on the file names. The setup periods, and the numbered notes that go with them, are documented in docs/Yearly_Notes.md and on the SwissFluxNet page it links to.

Four setup periods have no file in this folder:

  • 2019_2 (11 - 17 Jan 2019): the LI-7200 was replaced on 11 January 2019 and both units were defective, so the period has no usable gas fluxes. No sonic-only run for H has been made for it.
  • 2019_3 (17 Jan - 20 Mar 2019) was measured with the LI-7500 (IRGA75), which stood in for the defective LI-7200. It is processed with the other IRGA75 runs.
  • 2021_2 and 2022_1 (13 Dec 2021 - 7 Feb 2022) have no output at all: the raw data was logged in an unknown format and the conversion fails on an unrecognised record length.

These are the two long gaps of the merged record, 69 and 56 days, and the checks below assert that there are no others.

2018_3 (19 May - 7 Jun 2018) is a sonic-only run. The LI-7200 flow module had failed, so the run contributes H and no FC or LE.

The wrong calibration gas. All IRGA72 CO2 concentrations between 14 December 2017 and 15 March 2019 were measured against a wrong calibration gas, and the correction is a factor 0.974 on the CO2 concentration before the fluxes are calculated. It was applied during the conversion of the raw data to ASCII with bico, so these runs read corrected concentrations.

The biomet columns. Every run exported its six biomet inputs (TA_1_1_1, RH_1_1_1, PA_1_1_1, SW_IN_1_1_1, LW_IN_1_1_1, PPFD_IN_1_1_1) into the FLUXNET file. They are dropped: the meteo variables come from the 10_METEO products, not from the EddyPro output.

🕐 Timestamp convention and run overlaps

The EddyPro output carries TIMESTAMP_START and TIMESTAMP_END. Each file is read with output_middle_timestamp=True, so the merged record is indexed on TIMESTAMP_MIDDLE, the same convention as the Level-0 merge and the meteo products. Timestamps are used as written by EddyPro; nothing is shifted here.

Runs that meet at a year boundary overlap by six hours. Both include the raw file that starts at 19:00 on 31 December, so both write the 12 half-hours from 31 December 19:15 to 1 January 00:45. They are separate runs and their values there differ. MultiDataFileReader merges several files with combine_first, cell by cell, which keeps the earlier run’s value and fills only its gaps from the later run, so a single record could combine FC from one run with LE from the other. Each run is therefore read on its own, and each record is taken whole from one run: records before midnight from the earlier run, records from midnight on from the later one. Each calendar year then comes from the run made for it.

✂️ Run overlaps

Every pair of consecutive runs whose periods overlap is split at the one midnight inside the overlap. The table reports what the choice decides: the largest difference between the two runs over the records where both hold a value.

# KEEP[run] = (first, last) TIMESTAMP_MIDDLE taken from that run; None means the run's own end.
KEEP = {_run: [None, None] for _run in runs}
_rows = []
_names = list(runs)
for _a, _b in zip(_names, _names[1:]):
    _ov = runs[_a].index.intersection(runs[_b].index)
    if len(_ov) == 0:
        continue
    assert len(_ov) <= MAX_OVERLAP_RECORDS, f"{_a} and {_b} overlap by {len(_ov)} records"
    # The overlap must be one stretch at the end of the earlier run and the start of the later.
    assert _ov[0] == runs[_b].index[0] and _ov[-1] == runs[_a].index[-1], (
        f"{_a} and {_b} overlap other than end to start")
    _midnights = pd.date_range(_ov[0].ceil('D'), _ov[-1], freq='D')
    assert len(_midnights) == 1, f"the overlap of {_a} and {_b} does not contain exactly one midnight"
    _cut = _midnights[0]
    # The labels sit at :15 and :45, so the cut falls between two records rather than on one.
    KEEP[_a][1] = _ov[_ov < _cut][-1]
    KEEP[_b][0] = _ov[_ov >= _cut][0]
    _row = {'earlier run': _a, 'later run': _b, 'from': _ov[0], 'to': _ov[-1],
            'records': len(_ov), 'from earlier': int((_ov < _cut).sum()),
            'from later': int((_ov >= _cut).sum())}
    for _c in FLUXCOLS:
        _x, _y = runs[_a].loc[_ov, _c], runs[_b].loc[_ov, _c]
        _d = (_x - _y).abs()[_x.notna() & _y.notna()]
        _row[f'max |d{_c}|'] = _d.max() if len(_d) else float('nan')
    _rows.append(_row)

# The index must be continuous 30MIN, unique and ascending, and end at PERIOD_END.
assert df.index.is_monotonic_increasing, "timestamp index is not ascending"
assert not df.index.duplicated().any(), "duplicate timestamps in the merged record"
_steps = df.index.to_series().diff().dropna().unique()
assert len(_steps) == 1 and _steps[0] == pd.Timedelta(REQUIRED_TIME_RESOLUTION), \
    f"index is not continuous {REQUIRED_TIME_RESOLUTION}, found steps: {_steps}"
assert df.index[-1] == pd.Timestamp(PERIOD_END), f"the record ends at {df.index[-1]}"
assert df.dtypes.map(pd.api.types.is_numeric_dtype).all(), "a non-numeric column reached the merge"

# Every record holds exactly the values of the run it was taken from. This is what reading the runs
# separately is for, so it is tested on the merged frame rather than assumed.
_covered = pd.Series(False, index=df.index)
for _run, _df in runs.items():
    _lo, _hi = KEEP[_run]
    _own = _df.loc[_lo:_hi].loc[:pd.Timestamp(PERIOD_END)]
    _covered.loc[_own.index] = True
    for _c in FLUXCOLS:
        if _c in _own:
            pd.testing.assert_series_equal(df.loc[_own.index, _c], _own[_c], check_names=False,
                                           obj=f"{_c} of {_run}")

# Every record that some run holds is in the merge: the overlap cuts drop nothing.
_held = runs[EXPECTED_RUNS[0]].index
for _df in runs.values():
    _held = _held.union(_df.index)
_held = _held[_held <= pd.Timestamp(PERIOD_END)]
assert _covered.loc[_held].all(), (
    f"records held by a run are missing from the merge: {list(_held[~_covered.loc[_held].values])[:5]}")

# The stretches no run covers, longer than one day, are exactly the two explained ones.
_gap = ~_covered
_starts = df.index[_gap & ~_gap.shift(1, fill_value=False)]
_ends = df.index[_gap & ~_gap.shift(-1, fill_value=False)]
_long = [(_s, _e) for _s, _e in zip(_starts, _ends) if _e - _s >= pd.Timedelta('1D')]
print("Stretches no run covers:")

    f"the long gaps are not EXPECTED_LONG_GAPS: {_long}")
